A hard fork that makes over-cap blocks invalid. From block **50,000**, a
signed block whose signer has already used its cap of the last 1,440 blocks
is invalid, instead of valid at a tapered subsidy and a sliver of work.

**Every node must upgrade before block 50,000.** It is expected around 18
November 2026 UTC, depending on block times. A node on v1.3-DIMEBAG to
v1.3.2-DIMEBAG still accepts over-cap blocks, so it would follow a different
chain if one is produced.

## What changes

- **Over-cap blocks are invalid from 50,000:** `OVER_CAP_INVALID_FROM` is
  50,000. The test is the same as today's taper (`n > signer_cap`). A block
  at the cap is valid and counts in full; one past it is refused. Below
  50,000, nothing changes: over-cap blocks stay valid, pay the tapered
  subsidy, and add only a sliver of work.
- **Templates refuse to build one** from that height, and a headers-first
  sync refuses a signed header that claims the sliver.
- **Nothing else of consensus moves:** the cap itself (`CAP_WINDOW` 1,440,
  `CAP_K` 360, so a floor of 4 blocks a bond a day), unsigned-block rules,
  Midstate Walk from 37,300, and midstate's switch at 371,500 are unchanged.

## Mining

- **A valid block needs a bond under its cap.** After 50,000, a producer
  that is already over cap cannot extend the chain with another signed
  block. Register enough bonds for your hashrate before then: the same
  advice as today, now enforced.
- **Pools and solo miners** need this release on their midwimble node
  before block 50,000.

## Also in this release

- **`--max-orphan-depth` defaults to 100** (was 12). Nodes from before the
  sync fix for heavier-but-shorter chains (v1.2.2-DIMEBAG) still follow a
  replace of 12; `--max-orphan-depth 12` keeps that. This is local policy,
  not consensus. `--no-orphan-over-cap` is unchanged. Below height 50,000
  the same replacing still applies; from 50,000 there are no valid over-cap
  blocks for it to replace.
- **DNS transport** so `/dns4/` bootstrap addresses resolve (for example
  `/dns4/rpc.cypherpunk.gold/tcp/9433/p2p/12D3KooWCvjd2SBokjWMH712NXNFWHKr7kJAeBsUQ447LHk7wrzu`).
  The node uses Cloudflare's resolvers, so it does not depend on the
  machine's DNS settings.
- **`midwimble --version`** prints `1.4.0-DIMEBAG`. The crate version in
  Cargo.toml is now that release, instead of `0.1.0`.

## Upgrading

- **Every node:** upgrade before block 50,000.
- **Miners:** register bonds so you stay under the cap. After the height,
  an over-cap block is rejected, not merely tapered.
